# 交互动画规则

动画用于表达状态变化、空间关系和反馈，不用于填充空白。所有动画都必须能被关闭或尊重系统的 `prefers-reduced-motion`。

## 1. 基础时长

| 场景                     | 建议时长  | 缓动                        |
| ------------------------ | --------- | --------------------------- |
| hover、focus、颜色和边框 | 120–180ms | ease-out                    |
| 按钮反馈、标签状态切换   | 150–220ms | ease-out                    |
| 下拉、Popover、Tooltip   | 160–240ms | ease-out 进入，ease-in 退出 |
| Modal、Drawer、页面区域  | 220–360ms | ease-out 进入，ease-in 退出 |
| 大范围布局或跨层级转场   | ≤ 450ms   | 专用 cubic-bezier           |

超过 500ms 的动画必须有明确的空间叙事或用户阅读目的，否则会让后台操作感觉迟钝。

## 2. 可动画属性

优先使用 `transform` 和 `opacity`。颜色、边框和阴影只用于低频状态。避免对 `width`、`height`、`top`、`left`、`margin` 做高频动画，因为它们可能触发布局和重绘。

玻璃液态风格的 blur、光晕和渐变只作为装饰层，不能依赖动画才能看清文本；在低性能设备和 reduced motion 下关闭持续光效。

## 3. 状态要求

每个有动画的组件都要定义：

- 初始、进入、稳定、退出状态。
- hover、active、focus-visible、disabled、loading 状态。
- 内容变化时的布局行为，不能让焦点或主要按钮突然跳动。
- 动画中被用户再次操作时的中断和恢复行为。
- `prefers-reduced-motion: reduce` 下的静态替代效果。

## 4. React 动画边界

- CSS 能解决的过渡不引入 JS 动画库。
- 需要测量、编排或拖拽时，动画逻辑放在组件内部并保证清理监听器和 frame。
- 不在 render 中启动动画，不把每一帧写入 React state。
- 动画结束回调要处理组件卸载和用户快速重复操作。

## 5. 可访问性和性能

- 不使用闪烁作为提醒，任何内容不得超过 3 次/秒闪烁。
- 动画不能是理解状态的唯一信号，必须有文字、图标、结构或 aria 状态。
- 弹框打开后先移动焦点，关闭后恢复原触发元素焦点。
- 验收时同时检查 320px 宽度、200%/400% 缩放、暗色模式和 reduced motion。
