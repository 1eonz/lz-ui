# ADR-0005：Table 原生键盘交互模型

## 状态

**已接受。** 原“纯文本单元格方向键导航”P2 从当前缺陷清单中关闭，并作为原生静态表格的已接受限制记录。本决策不表示组件已经提供单元格网格导航，也不代表真实屏幕阅读器或完整无障碍验收通过。

## 背景

`LxTable` 是 Ant Design 5 Table 的薄适配层，透传公开的 `TableProps`，不接管业务数据、行操作和焦点状态。当前 Table 使用原生表格语义。普通宽表格文档示例额外提供一个具名、可聚焦的滚动区域；该区域聚焦时，无修饰的左右方向键只用于横向滚动，且只有滚动位置实际改变时才取消浏览器默认行为。方向键不在纯文本单元格之间移动焦点。

固定列由 Ant Design 自身的内部滚动区实现。Ant Design 5.24 没有直接暴露该默认内部横向滚动区的 prop/ref 来配置名称、焦点或键盘滚动协议；公开的 `LxTableRef.scrollTo` 支持按行（`index`/`key`）或垂直位置（`top`）定位，不提供横向位置参数。`onCell` 可为单元格注入属性，`components.body.cell` 和 `components.body` 可用于自定义单元格或 body 渲染；宿主可基于这些公开扩展点自建键盘行为，但它们不提供现成的 roving focus、键盘协议、焦点恢复或虚拟行协调能力。

WAI-ARIA Authoring Practices Guide 将 Table 定义为静态表格结构，并将 Grid 定义为需要作者管理焦点的复合交互控件，见 [Table Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/table/) 和 [Grid Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/grid/)。Data Display 设计稿要求 WCAG 2.2 AA 和清晰焦点环，没有要求类似电子表格的单元格方向键遍历。此前将纯文本格方向键导航缺失单独标为 P2，容易把静态表格与交互式网格混为同一契约。

## 决定

### 保留原生静态表格语义

- Table 保留原生 `table` 语义；不在 Table、行或单元格上添加 `role="grid"`，不把纯文本单元格加入 Tab 顺序，也不在适配层统一拦截单元格方向键。
- 单元格内的复选框、链接、按钮和其他真实控件继续使用自身原生或公开组件键盘行为，并按正常 Tab 顺序到达。
- 普通溢出演示区域可使用外部具名滚动区域提供横向键盘滚动。这是文档示例的滚动辅助能力，不是单元格导航，也不改变 `Table` 公开 API。
- 固定列继续由 Ant Design 的公开 Table 配置负责。不得读取 Ant Design 私有 DOM、依赖未公开 rc-* 接口，或通过运行时改写角色补出焦点入口。
- 当前固定列示例的行操作可打开具名详情区域，按分组阅读该行字段；这是该示例提供的替代阅读路径，不构成所有宿主 Table 的通用保证。

### 将方向键网格导航留给独立设计

若后续业务明确要求电子表格式遍历，应单独评审 opt-in 网格能力，优先考虑独立 Grid 组件或明确分离的模式，不把半套焦点逻辑悄悄加入默认 Table。该设计至少要规定并验证：

- roving tabindex、方向键、Home/End、PageUp/PageDown、Ctrl+Home/Ctrl+End、Tab 进出网格和焦点恢复。
- 单元格内按钮、复选框、链接、编辑控件的进入/退出规则，以及排序、选择、展开行和受控状态。
- 固定列、横向/纵向滚动、虚拟化、动态行高、卸载后焦点恢复和 RTL。
- `table` 与 `grid` 的 ARIA 语义、屏幕阅读器实际行为、窄屏、缩放和 reduced motion 验收。

## 未选择的方案

- **默认给每个单元格加 `tabIndex` 并处理左右键：** 会改变静态表格的焦点顺序，却没有建立完整的网格模式；大量单元格也会增加 Tab 停靠点并干扰单元格内控件。
- **直接把现有 Table 改成 `role="grid"`：** 只改角色不足以构成 Grid。若没有完整 roving focus 和控件交互协议，读屏用户会收到与实际行为不匹配的语义。
- **依赖 Ant Design 私有滚动节点：** 会耦合具体 DOM 结构和版本，升级风险高，且违反项目禁止使用私有 DOM 的规则。
- **把自建行为视为现成的公共 Table 能力：** `onCell`、自定义 cell 等扩展点允许宿主实现，但行为、无障碍和与固定列/虚拟化的协调责任仍由宿主承担。

## 优点与代价

优点是默认 Table 保持 Ant Design 的原生语义和可预测的 Tab 顺序，不承诺无法完整实现的网格协议；普通宽表格仍有独立横向滚动入口，单元格交互控件不被外层抢键。

代价是纯文本单元格不会成为键盘焦点目标。屏幕阅读器软件可能提供自己的表格浏览方式，具体行为取决于软件、浏览器和当前模式；本项目尚未完成真实读屏验证，不能据此宣称兼容。不使用屏幕阅读器的键盘用户不能通过 Tab 逐格遍历纯文本。固定列模式也没有可直接聚焦和配置其默认内部滚动区的 prop/ref。业务若需要逐格键盘操作，应使用具备该能力的网格方案或等待单独设计的 lx-ui Grid，而不能把本 ADR 当作满足该需求的证明。

## 验收与边界

- Table 文档说明静态表格与单元格网格的行为差异，并链接本 ADR。
- 现有浏览器测试覆盖普通滚动区域的横向滚动、边界默认行为、修饰键与子控件透传；固定列测试覆盖 Tab 到达真实操作控件和行详情阅读路径。它们不证明屏幕阅读器支持或 cell-to-cell 导航。
- 本 ADR 不改组件代码、公开 API、运行时依赖或浏览器行为；不关闭 Table 全部矩阵或全库 2B-1。
- 任何“键盘完整通过”或“无障碍完整通过”的发布结论仍须等待真实屏幕阅读器及其余未覆盖矩阵。

## 重新评估条件

当 ERP/CRM 用户提出可复现的逐单元格键盘操作需求、读屏实测发现当前静态语义存在具体缺陷，或产品规格明确要求电子表格交互时，重新开展独立 Grid 设计与架构评审。重新评估前，不在默认 Table 中加入隐式网格行为。
