# 发布和版本规则

## 1. 当前保护

工程当前 `private: true`，用于防止 P0 实现阶段误发布。完成组件、文档、测试、体积和迁移检查后，才可以由负责人把它改成 `false` 并配置真实 npm 私库 registry。

不要把账号、token、私库地址密钥或机器相关配置提交到仓库。使用 `.npmrc.example` 说明配置方式，在本机或 CI secret 中注入真实值。

## 2. 版本策略

- `0.x`：允许在真实项目试用，但公共 API 仍可能调整。
- `1.0.0`：P0 基础和业务组件完成稳定 API、文档和迁移路径后发布。
- patch：修复兼容问题、文档问题和无行为变化的性能修复。
- minor：新增向后兼容组件、props、主题 preset 或文档能力。
- major：删除/改名公开 API、改变默认交互或放宽/收紧 peer 范围。

## 3. 变更记录与 Changesets

当前先维护 `CHANGELOG.md` 和对应 ADR；Changesets 尚未安装，首次发布前必须接入并验证版本命令。公共 API、主题 token、依赖、构建出口和组件行为变化都要记录用户影响和迁移方式，不能只写“更新组件”。接入 Changesets 后，每个此类改动还须附 changeset。

## 4. 发布流程

1. 合并前通过所有检查和视觉回归。
2. 运行 `npm pack --dry-run`，确认只包含 dist、README、CHANGELOG 和许可证文件。
3. 检查 `exports`、peer dependency、版本和 CHANGELOG。
4. 在私库发布候选版本，使用真实项目安装验证。
5. 再发布正式版本并记录回滚版本。

## 5. 回滚

发现高风险问题时优先撤回受影响版本的使用入口，发布包含修复的 patch。不要删除已经发布的版本或复用同一个版本号。
